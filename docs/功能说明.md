| 项 | 内容 |
| --- | --- |

## 一、一句话概括

**点「编辑」不跳到源码框 —— 排版不变，直接改。**

除所见即所得编辑外，同一个版本里还带一个完整的设置面板、一套内容保真处理，
以及「双击打开」链路上的一批可靠性处理。

---

## 二、能力详解

### 1. 所见即所得编辑

点「编辑」后，预览区**原地变成可编辑容器** —— 字体、字号、行距、代码底色的观感完全不变，
不会切到另一个源码框。

- **保真优先**：以 Markdown 的词法块为「编辑单元」，**没改过的块直接用原文切片回写**，
  只有真正动过的那一块才会被重新序列化。于是「打开 → 编辑 → 保存」在没改东西时是
  **逐字节零改动**的 —— 表格对齐、代码围栏语言、任务列表标记、引用层级都不会被改写。
- **自动退化**：词法库缺席、或切分无法无损拼回原文时，自动回到源码编辑并在状态栏说明原因，
  不给出「看着能编辑、其实没反应」的界面。
- **行内语法靠 DOM 结构表达**：粗体 / 斜体 / 行内代码 / 链接 / 图片 / 删除线 / 任务列表复选框；
  段落行首会被误认为结构语法的字符（`#` `>` `|` `-` `1.`）自动补反斜杠转义，
  不让一段普通文字退化成标题或列表。
- **日常细节**：粘贴只收纯文本（外部 HTML 会污染 DOM 与源码）；编辑态点链接不跳转、点图片不弹灯箱；
  `Esc` 退出编辑、`Ctrl+S` 保存；切换标签 / 关闭标签 / 保存前自动提交，不会吞掉刚敲的内容。

### 2. 源码字节零改动

| 场景 | 行为 |
| --- | --- |
| CRLF 文件进过一次「编辑」 | 打开时记下换行风格与 BOM，落盘按记录还原，**不会把整份行尾改成 LF** |
| 带 BOM 的文件保存 | 统一按**字节**判定 BOM，扩展端与 Windows 端行为一致 |
| 一个字符都没改就保存 | **逐字节回放原始文本**，磁盘上一个字节都不动 |

### 3.「源码」按钮：随时往返

编辑态下可在「所见即所得 ↔ 源码」之间随时切换，两种方式**共用同一份内容**、互不覆盖；
源码编辑保留原有能力（全文搜索定位、Tab 缩进、行号语义）。

### 4. 设置面板

观感与行为参数全部收拢成一份可配置的定义表，并给出可视化界面 ——
想调正文字号、想关掉某个按钮，都不必再动源码。

| | 能力 |
| --- | --- |
| ⚙️ | **设置面板** —— 扩展端独立选项页（右键扩展图标 →「选项」）；Windows 端编辑器内弹层 |
| 🎛️ | **16 项可调参数** —— 主题 / 界面语言 / 正文字号 / 行高 / 阅读宽度 / 界面动效 / 源码字号 / 缩进宽度 / 拼写检查 / 复制按钮 / 公式渲染 / 图片放大 / 自动刷新 / 关闭确认 / 离开提醒 / 侧栏自动展开 |
| 🧩 | **一处定义，处处生效** —— 界面由 `SCHEMA` 定义表现场生成，新增一个设置只改一处 |
| 🔁 | **自动刷新已打开文件**（默认关闭）—— 磁盘被外部改动时自动重载；当前标签有未保存内容时**只提示、不覆盖** |
| 📤 | **导出 / 导入设置** —— `MDTN-SET/1` 明文（带 `MDTN-F1` 指纹校验）或 `MDTN-E1` 口令封装 |
| ⌨️ | **`Ctrl+,` 打开设置面板** |

### 5. 扩展卡片不挂「警告」

清单里声明的 `file_handlers` 只被 Chrome 授权给 packaged app，而它本身又是 **ChromeOS 独占**能力 ——
Windows / macOS / Linux 上不注册任何系统关联，属于「功能拿不到、警告一直挂」。本项目不声明该键，
扩展卡片上的「警告」按钮因此不会出现。`launchQueue` 消费逻辑保留，需要时可直接复用。

---

### 6. 代码带作者署名（原创主张）

每个一方源码文件的首行都带一行 **`MDTN-A1` 署名**，用 Ed25519 非对称签名：

- **只有持有私钥的人签得出来**，任何人拿到仓库或安装包都能用 `AUTHOR.pub` **验证** —— 别人抄不走这个身份；
- 文件被**原样搬运**时署名跟着走；被**改动**时署名立即失效，`node tools/author.js check` 会点名报出；
- 私钥 `author.key` 放在**仓库外**（默认 `%USERPROFILE%\.mdtn-author\author.key`），永不入库、不随包分发；
  公钥 `AUTHOR.pub` 入库并镜像进两个安装包，所以**任意一个包都能独立验签**。

与 `MDTN-F1` 指纹分工不同：`MDTN-F1` 是**对称**的完整性自证（谁都能重算），
`MDTN-A1` 是**非对称**的原创署名（谁能签、谁能验是分开的）。

## 三、容易踩到的情况，现在的处理方式

| # | 现象 | 原因 | 现在的行为 |
| --- | --- | --- | --- |
| 1 | Windows 版用**「打开」按钮**选中的文件，改完点保存**文件没变**，界面也不报错 | 只有文件句柄、没有磁盘路径的文档，被交给了按「绝对路径」寻址的宿主，宿主沉默退出 | 内核只在**确有磁盘路径**时才把保存交给宿主，其余一律回落文件句柄写回 |
| 2 | 保存被取消或写入失败时，界面**什么都不发生** | 宿主与内核都没说明原因 | 状态栏给出明确提示，杜绝「点了保存却没反应」 |
| 3 | 双击 `.md`：**服务起来了，页面却是空的** | 同机两份副本各有各的 Token 却共用同一端口；启动器只探端口、不验 Token 就复用 → `/api/*` 一律 **403** | `/api/ping` 如实回答「认不认你的 Token」（`mine`）与「服务在哪个目录」（`root`）；端口上是**别人的**实例就自动换一个空闲端口起本副本的服务，文件照常打开 |
| 4 | 安装目录被删除 / 移动后，双击 `.md` **完全没反应**，日志里也没有新增行 | 关联指向了不存在的路径，脚本宿主连入口都找不到 | 安装脚本会先读出现有关联，并明确区分「那份还在（本目录会把它顶掉）」与「那条关联已失效（目录不存在）」 |
| 5 | 源码态点「查看预览」会**丢掉刚改的内容** | 切回预览时只在富文本态收内容 | 切换前先提交当前编辑态 |
| 6 | 新增的块与**上一段粘成一段** | 重新序列化的块前面没补空行，被 Markdown 当作上一段的惰性续行 | 回写时补空行 —— 这是「编辑之后格式变了」最典型的来源 |
| 7 | 导入设置时口令填错，报的是「正文不是合法 JSON」 | `MDTN-E1` 是流式混淆、无内建校验，口令错时解出来的是乱码 | 识别为「口令不正确或内容已损坏」，提示有明确指向 |
| 8 | 极低概率出现 **4 位校验尾**，与格式约定（3 位 Base36）冲突 | `sig.js` 的 `base36()` 在摘要值 ≥ 46656 时未定长输出 | 先对 36³ 取模再定长输出 |

## 四、怎么安装

### ① 浏览器扩展

1. 解压 `md-tiny-extension-v1.0.zip`
2. 打开 `chrome://extensions`（Edge 用 `edge://extensions`），开启右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择解压出的 `md-tiny-extension` 目录
4. 设置保存在 `localStorage` / `chrome.storage.sync` 中

### ② Windows 本地启动器

1. 解压 `md-tiny-win-v1.0.zip` 到**固定位置**
   （建议 `%LOCALAPPDATA%\Programs\md-tiny-win`，别放 `Downloads`）
2. 想先看它会做什么、不动注册表：`node install.js --dry-run`（只读，不会留下任何文件）
3. 双击 `安装.cmd`
4. 装完双击任何 `.md` 就能用本编辑器打开，`Ctrl+S` 直接写回原文件

> 前提：已安装 [Node.js](https://nodejs.org/) 并在系统 PATH 中。**无需 `npm install`，零第三方依赖。**

> ⚠ **一台机器只保留一份已安装副本。** 文件关联属于**当前用户**、全局只有一份：在另一个目录再跑一次
> 安装，会把原来那份顶掉（脚本会把新旧目录都打印出来）。两份副本还会共用同一端口，
> 这正是「服务起来了、页面是空的」的成因。
>
> ⚠ **不要把 `dist/` 这类会被重建的构建产物目录当作安装位置** —— 目录一旦被换掉，
> 双击 `.md` 会变成「完全没反应」，且日志里没有任何线索。

> 如果你的 `.md` 默认程序曾**手动指定**过（`UserChoice`），它的优先级高于安装脚本，
> 需要去「设置 → 应用 → 默认应用」里再选一次「md-tiny」；否则双击立刻生效。

## 五、注意事项

- **混合行尾**的文件（同一份文档里 CRLF 与 LF 混杂）在编辑保存后**按多数派统一**；
  只有「一个字符都没改」时才逐字节回放。
- 富文本层只覆盖 marked 会产出的那套标签。文档里手写的**原始 HTML 段与链接定义不参与编辑**
  （整块原样带走，界面里会标灰）。
- 数学公式在编辑态以 `$…$` 源码呈现（与 Typora 同样的取舍），退出编辑立刻变回渲染结果。
- 编辑态里输入 `2 * 3 * 4` 这类**成对符号**，保存后会被 Markdown 当成斜体语法 ——
  行内语法靠 DOM 结构表达，这是该实现方式的固有代价。
- Windows 版的保存分两条路：**双击关联 / 侧栏文件树**打开的文档走本地服务原子写
  （带 mtime 冲突检测、BOM 记账）；用**「打开」按钮**选中的文档走浏览器文件句柄直接写回
  （网页拿不到本地绝对路径，这是唯一途径），不经过服务端。
- 可编辑的类型是 `.md` / `.markdown` / `.mdown` / `.txt`；其它扩展名既不出现在侧栏，双击也不关联。

## 七、校验发布包

```bash
node tools/author.js check   # 复核源码作者署名（逐文件验签）
node tools/fingerprint.js    # 打印内核 / 富文本层 / 设置导出 / 两个交付包的当前指纹
node tools/build.js          # 同步内核 + 打两个 zip + 打印 SHA256
node tools/build.js verify   # 复核包签名 + 扩展与 win/web 的内核是否逐字节一致
```

每个包根目录都带 `BUILD.SIG`（逐文件 SHA256 + 内容指纹），可离线复核，无需信任分发渠道。
