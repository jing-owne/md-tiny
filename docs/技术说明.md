## 两个交付物，怎么选

|  | **① 浏览器扩展** | **② Windows 本地启动器** |
| --- | --- | --- |
| 目录 | [`extension/`](../extension/) | [`win/`](../win/) |
| 版本 | **v1.0** | **v1.0** |
| 安装包 | [仓库内](../dist/md-tiny-extension-v1.0.zip) | [仓库内](../dist/md-tiny-win-v1.0.zip) |
| **双击 `.md` 直接打开** | ❌ 平台不支持（见下） | ✅ |
| 写回原文件 | File System Access API | 本地 HTTP 服务（原子写 + 冲突检测） |
| 设置面板 | 独立选项页（`options.html`） | 编辑器内弹层 |
| 是否常驻 | 无 | 服务 30 分钟无请求自动退出 |

**两者是并列的，不是替代关系**：桌面日常用 ②，浏览器里随手改 Markdown 用 ①。
② 的编辑器页面就是 ① 的 `editor.js`（**逐字节一致**，由 `tools/build.js` 自动镜像），差异只有一组宿主扩展点 `window.MDTiny` —— 不注入时行为完全相同。

### 为什么扩展不能双击打开 .md

两件事叠加，导致这条路走不通：

1. **`file_handlers` 本身是 ChromeOS 独占能力**（扩展侧 Chrome 120+），Windows / macOS / Linux 上不注册系统关联；
2. 更关键的是，Chrome 的清单特性表把 `file_handlers` **只授权给 packaged app**。普通扩展一旦声明，加载时就会挂上一条安装警告，扩展卡片上出现「警告」按钮 —— 功能拿不到，警告却一直挂着：

   ```
   'file_handlers' is only allowed for packaged apps, but this is a extension.
   ```

因此 **v1.0 起已从 `extension/manifest.json` 中移除该键**，清单加载零警告。

| 平台 | 扩展的 `file_handlers` | PWA 的 `file_handlers` |
| --- | --- | --- |
| ChromeOS | ⚠️ 声明后可用，但会带上述安装警告 | ✅ 生效 |
| **Windows / macOS / Linux** | ❌ 无效，且带安装警告 | ✅ 生效 |

`editor.js` 里 `launchQueue` 的消费逻辑**保留**（PWA 形态或自行加回该键的构建可直接复用；其余环境为无害空转）。

<details>
<summary>ChromeOS 用户：想恢复「打开方式」关联，把这段加回 <code>extension/manifest.json</code></summary>

```json
"file_handlers": [
  {
    "action": "/editor.html",
    "name": "__MSG_extName__",
    "accept": {
      "text/markdown": [".md", ".markdown", ".mdown"],
      "text/plain": [".txt"]
    },
    "launch_type": "single-client"
  }
],
```

加回后 Chrome 会重新给出上面那条警告，属预期行为（Chrome 的授权范围如此，不是配置写错）。

</details>

**Windows 上要实现「双击 `.md` 用本编辑器打开」，用另一个交付物：[`win/`](../win/) 本地启动器。**

### ② 的安全加固（本地 HTTP 服务）

| 风险 | 对策 |
| --- | --- |
| 其它网站调本机接口偷文件 | 所有 `/api/*` 强制 **Token 鉴权**（48 位随机，存 `config.json`，仅本机可读） |
| DNS rebinding（恶意域名解析到 127.0.0.1） | 校验 **Host 头**，非 `127.0.0.1` / `localhost` 一律 403 |
| 局域网其它机器访问 | 只 `bind 127.0.0.1`，不监听 `0.0.0.0` |
| 静态目录被穿越读到代码 | 路径前缀校验 + 拒绝 `..`（含 URL 编码形式） |
| 请求体撑爆内存 | 上限 32 MB |

Token 通过 URL 传给页面，页面读取后立即 `history.replaceState` 抹掉地址栏参数，不留在浏览历史里。

## 自有文本格式

实现见 [`extension/sig.js`](../extension/sig.js)（指纹与封装）、[`extension/settings.js`](../extension/settings.js)（设置导出）
与 [`tools/author.js`](../tools/author.js)（作者署名）。

```
署名   MDTN-A1 <版本> <keyid> <签名>              （每个源码文件首行，Ed25519）
       MDTN-A1 1.0 12823B20 <86 字符 Base64URL>

指纹   MDTN-F1 <版本> <b0 b1 b2 b3 b4 b5 b6 b7> <校验尾>
       MDTN-F1 1.0 06 50 01 23 FE FC 80 D1 VDM

封装   MDTN-E1 <轮数> <c0 c1 c2 ... >            （两位十六进制、单空格分隔、每 16 字节换行）
       MDTN-E1 3 F5 9D 85 BA 21 27 20 E8 F8 9D D1 8F CC 8F 41 4A
               A3 91 43 A4 4C 0E 42 AC 50 F0 F4 DC 59 53 ED FD

设置   MDTN-SET/1 <版本> <指纹> <正文 JSON>       （导出设置用）
       MDTN-SET/1
       version: 1.0
       fingerprint: MDTN-F1 1.0 50 57 5C A8 91 3E 99 C2 V90
       ---
       { "content.fontSize": 16, ... }
```

### `MDTN-A1` —— 作者署名（原创主张）

**它和 `MDTN-F1` 不是一回事**，这是本套格式里唯一的**非对称签名**：

| | `MDTN-F1` 指纹 | `MDTN-A1` 署名 |
| --- | --- | --- |
| 算法 | 自有混洗（对称） | Ed25519（非对称） |
| 谁能生成 | 任何人 | **只有持有私钥的人** |
| 谁能验证 | 任何人（重算即可） | 任何人（用 `AUTHOR.pub`） |
| 用途 | 产物完整性自证 | **主张原创**：别人能验证、不能伪造 |

- **签名覆盖内容**：把「署名行」和「指纹行」都剔除后的文件正文。
  - 剔署名行 —— 否则署名行自己也在被签内容里，写进去就对不上（自我引用）；
  - 剔指纹行 —— `editor.js` / `richedit.js` 里嵌着 `MDTN-F1`，而该指纹又依赖正文；两者若互相依赖就是死循环。剔掉后依赖是单向的：**先署名，再算指纹**。
- **密钥分工**：
  - 私钥 `author.key` —— **放仓库外**（默认 `%USERPROFILE%\.mdtn-author\author.key`），永不入库、永不随包分发；
  - 公钥 `AUTHOR.pub` —— 入库，并镜像进 `extension/` 与 `win/`，所以**任意一个安装包都能独立验签**；
  - `keyid` —— 公钥 SPKI DER 的 SHA256 前 8 位十六进制，写在每个署名行里，用来对应到具体公钥。
- **怎么理解它的证明力**：署名行随源码走。别人把文件**原样抄走**，你的署名就跟着到了对方仓库，且能被独立验证；
  他一旦**改动内容**，署名即失效并会被 `check` 点名。它挡不住「删掉署名重写一遍」，那是任何水印类手段的共同边界 ——
  但「原样搬运」和「改动后冒名」这两种情形都会被稳定地暴露出来。

### 怎么用

```bash
node tools/author.js init    # 首次：生成密钥对（私钥写仓库外，公钥入库 + 镜像进两个交付目录）
node tools/author.js stamp   # 写完代码后跑一次：给全部一方源码重新署名
node tools/author.js check   # 验签：逐文件核对，失败退出码 1
node tools/author.js list    # 列出哪些文件带了署名
node tools/author.js where   # 打印密钥位置与 keyid
```

看署名：任意一方源码的**首行**，形如 `MDTN-A1 1.0 12823B20 <签名>`。
签名按文件类型换注释符号：`.js` 用 `//`、`.css` 用块注释、`.html` 用 HTML 注释；带 shebang 的脚本插在 shebang 之后。

> **改动源码后必须重新 `stamp`**，否则 `check` 会报「内容与署名不符」。
> 同理，署名改变正文会让 `MDTN-F1` 失效，所以推荐顺序是：`stamp` → `fingerprint.js` 回填 → `build.js`。

### 其他三点

- 指纹用于**产物自证**：每个安装包根目录的 `BUILD.SIG` 记录逐文件 SHA256，再对摘要串取指纹
- 封装是**流式混淆**（自有编码，不兼容任何通用加密标准），用于内部数据落地与往返校验
- `MDTN-SET/1` 用于**设置导出**：导入时比对头部指纹，内容被改动过会明确提示"不一致"而非静默接受；
  导出也可选择 `MDTN-E1` 口令封装，导入需同一口令
- `MDTN-F1` 与 `MDTN-E1` **不具备密码学强度**，不要用来保护机密数据；`MDTN-A1` 用的是标准 Ed25519

复核方式：

```bash
node tools/author.js check     # 作者署名：逐文件验签
node tools/build.js verify     # 校验包内 BUILD.SIG 与当前文件是否一致
node tools/fingerprint.js      # 打印内核 / 富文本层 / 设置导出 / 两个交付包的当前指纹
```

## 构建与打包

```bash
node tools/author.js stamp     # 给一方源码重新署名（改过代码就跑）
node tools/build.js            # 同步内核到 win/web + 生成 BUILD.SIG + 打包 dist/*.zip + 打印 SHA256
node tools/build.js sync       # 只做内核同步
node tools/build.js verify     # 只做签名复核（含内核镜像逐字节比对）
```

打的 zip 不依赖任何第三方打包工具（内置 zlib 实现），设置 `SOURCE_DATE_EPOCH` 可让产物可复现。

> 开发期自测脚本（`win/test-*.js`、`tools/test-*.js`）只保留在本机源码树，**不入库、也不随包分发**。
> 需要时在本地跑：接口与安全 29 项、启动链路 23 项、端到端 57 项（需 Chrome）、设置中心 57 项、富文本层 35 项（需 Chrome）。

打 tag（形如 `v1.0`）后由 [`.github/workflows/release.yml`](../.github/workflows/release.yml) 自动完成
「版本一致性校验 → 构建 → 签名复核 → 生成 `SHA256SUMS` → 发布 Release」。

> ⚠️ **`README.md` 与 `AUTHOR.pub` 都在发布包里**（`extension/` / `win/` 下除点开头的项之外都会被打包），
> 所以改动它们之后必须重新 `build.js`，否则 `verify` 会报不一致。

## 第三方依赖与许可

`lib/` 下的库均为原样引入，遵循其各自许可：

| 库 | 用途 | 许可 |
| --- | --- | --- |
| [marked](https://github.com/markedjs/marked) | Markdown → HTML | MIT |
| [DOMPurify](https://github.com/cure53/DOMPurify) | HTML 消毒 | Apache-2.0 / MPL-2.0 |

| [github-markdown-css](https://github.com/sindresorhus/github-markdown-css) | 预览样式（主题块已改写以支持手动切换） | MIT |
| [KaTeX](https://github.com/KaTeX/KaTeX) | 数学公式 | MIT |

本仓库自身的应用代码以 [MIT](../LICENSE) 许可发布。作者署名工具用的是 Node 内置 `crypto` 的标准 Ed25519，无第三方依赖。
