# md-tiny · Windows 双击打开方案（本地启动器）v1.0

解决一个问题：**在 Windows 资源管理器里双击 `.md`，直接用本编辑器打开、编辑、`Ctrl+S` 写回原文件。**

- 环境：Windows + Node.js（在系统 PATH 中），**零 npm 依赖**
- 体积：约 **528 KB**（含本地 KaTeX 字体，公式组件约占 333 KB；去掉公式组件后约 185 KB）
- 版本：**v1.0**
- 界面语言：简体中文 / English 自动识别，可手动切换（其他语言回落英文）
- 设置：**16 项参数**可在编辑器内弹出面板中调整（工具栏 `⚙` 或 `Ctrl+,`）

---

## 为什么需要这个东西

浏览器扩展**做不到**这件事，这不是实现水平问题，是平台限制：

| 平台 | 扩展的 `file_handlers` | PWA 的 `file_handlers` |
| --- | --- | --- |
| ChromeOS（Chrome 120+） | ⚠️ 声明后生效，但会被判「仅限 packaged app」并带一条安装警告 | ✅ 生效 |
| **Windows / macOS / Linux** | ❌ **无效**，且同样带安装警告 | ✅ 生效（Chrome/Edge 102+） |

也就是说：

- **扩展**在 Windows 上无法注册系统文件关联 —— 双击永远走不到编辑器；而声明 `file_handlers` 只会换来一条安装警告（v1.0 起扩展端已移除该键，见 [`extension/README.md`](../extension/README.md)）
- **PWA** 可以，但需要一个可访问的 https 源，且首次双击会弹一次授权

而本方案不依赖上面任何一条：它用一个**几十 KB 的本地小程序**把「文件关联 → 读文件 → 写回文件」这条链路打通，**100% 离线、不需要公网、不需要管理员权限、不需要装扩展**。

## 功能

### 打开与写回

- **双击 `.md` 直接打开** —— 注册 `.md` / `.markdown` / `.mdown` 系统关联（写入 `HKCU`，**无需管理员**）
- **`Ctrl+S` 写回原文件** —— UTF-8 纯文本原样写回，**格式零改动**
- **字节保真** —— 打开时记下换行风格（CRLF / LF）与 BOM，落盘按记录还原；**一个字符都没改时逐字节回放**
- **无黑框闪烁** —— 关联目标是隐藏窗口的脚本宿主，双击不弹命令行窗口
- **原子写** —— 先写同目录临时文件再 rename 覆盖，写入中断不会损坏原文件
- **冲突检测** —— 保存时比对 mtime，文件被外部改过则弹确认，不会静默覆盖
- **保留 BOM 与 CRLF** —— 中文与换行不被破坏（本地服务端管 BOM，编辑器内核管换行）

### 编辑器能力（与扩展版同源）

- **打开即预览** —— GFM 表格、任务列表、脚注、引用
- **所见即所得编辑** —— 点「编辑」后预览区直接可改，排版不变；未改动过的块按原文回写
- **源码编辑 / 预览切换** —— 编辑态一键在「所见即所得 ↔ 源码」之间往返
- **代码高亮** —— Prism 合并包，覆盖 40+ 种语法
- **数学公式** —— 正文出现公式时才加载 KaTeX；没有公式的文档零额外请求
- **深色 / 亮色主题** —— 三态：亮色 / 暗色 / 跟随系统，`Ctrl+Shift+L` 切换
- **大纲侧栏** —— 侧栏「文件 / 大纲」双栏，标题随正文滚动高亮，点击跳转
- **代码块一键复制**
- **图片点击放大** —— 灯箱查看，`Esc` 退出
- **HTML 消毒** —— DOMPurify 剥除恶意脚本与事件属性
- **多标签** —— 未保存标 `●`
- **文件树** —— 自动列出当前文件所在目录
- **全文搜索**
- **中英文界面** —— 自动识别浏览器语言，`中 / EN` 按钮一键切换
- **设置面板** —— 工具栏 `⚙` 或 `Ctrl+,` 打开；正文字号 / 行高 / 阅读宽度 / 源码字号 /
  缩进宽度 / 拼写检查 / 复制按钮 / 公式渲染 / 图片放大 / 自动刷新 / 关闭确认 等 16 项
  - **自动刷新**：打开的文件被别的程序改动时自动重载（默认关闭）；当前标签有未保存内容时
    **只提示、不覆盖**
  - 设置可导出为 `MDTN-SET/1` 文本（带指纹校验）或 `MDTN-E1` 口令封装，也可一键恢复默认
- **未保存离开提醒**、**Tab / Shift+Tab 缩进**（缩进宽度跟随设置）

#### 快捷键

### 安全（本地 HTTP 服务）

| 风险 | 对策 |
| --- | --- |
| 其它网站调本机接口偷文件 | 所有 `/api/*` 强制 **Token 鉴权**（48 位随机，存 `config.json`，仅本机可读） |
| DNS rebinding（恶意域名解析到 127.0.0.1） | 校验 **Host 头**，非 `127.0.0.1` / `localhost` 一律 403 |
| 局域网其它机器访问 | 只 `bind 127.0.0.1`，不监听 `0.0.0.0` |
| 静态目录被穿越读到代码 | 路径前缀校验 + 拒绝 `..`（含 URL 编码形式） |
| 请求体撑爆内存 | 上限 32 MB |

Token 通过 URL 传给页面，页面读取后立即 `history.replaceState` 抹掉地址栏参数，不留在浏览历史里。

### 运行方式

- **不常驻** —— 服务 30 分钟无请求自动退出，下次双击按需拉起（约 0.3 秒）
- **不引入任何新二进制** —— 纯 Node + 系统自带脚本宿主，规避杀软与智能应用控制拦截
- **卸载干净** —— 只删自己的注册表项与值，并还原安装前的扩展名默认程序

## 安装（一步）

```
双击 安装.cmd     （写入 HKCU 注册表，不需要管理员）
```

装完**双击任何 `.md` 就能用本编辑器打开**，`Ctrl+S` 直接写回原文件。

安装脚本会把 `.md` / `.markdown` / `.mdown` 的默认处理程序指向本程序。原值记录在 `assoc-backup.json` 里，卸载时自动还原。

> 想先看会发生什么、不动注册表：`node install.js --dry-run`（只读，不会生成 `config.json`）

### 关联是全局的：一台机器留一份就好

文件关联写在**当前用户**下，同一时刻**只有一份**生效。在另一个目录再跑一次 `安装.cmd`，
就会把原来那份顶掉 —— 脚本现在会先把**新旧两个目录**都打印出来，别忽略那段输出。

两份副本各有自己的 `config.json`（端口相同、Token 不同）。若旧副本的服务还在跑，端口上应答的
就是旧副本：启动器会**自动改用其它空闲端口**拉起本副本的服务，文件照样能打开，不再白屏；
但最干净的做法仍是只留一份（或先在任务管理器里结束那个 `node.exe`）。

> ⚠ **不要把 `dist/` 这类会被重建的构建产物目录当作安装位置。** 目录一旦被清理 / 换掉，
> 关联就指向了不存在的路径 —— 此时双击 `.md` **完全没反应**，且 `vbs.log`、`launch.log`
> 一行都不会新增，现象与「从没装过」一模一样。重新解压到固定目录再跑一次 `安装.cmd` 即可恢复；
> 到时 `node install.js` 会先把这条失效关联打印出来。

### 为什么「设置 → 默认应用」里找不到「md-tiny」？

这是 Windows 的取名规则导致的，**那个应用其实在列表里**：

「打开方式」列表里的**应用名**不是取注册项里的 `FriendlyAppName`，而是拿 `shell\open\command` 里那个 **exe** 去 `HKCR\Applications\<exe>` 下查名字。本程序为了不闪黑框，命令是：

```
wscript.exe //B open-md.vbs "%1"
```

于是 Windows 查到的是 `wscript.exe` → 显示成 **「Microsoft ® Windows Based Script Host」**。
**列表里这一条就是本编辑器**，选它并设为默认即可。

同时脚本还注册了 `Applications\MDTiny.exe`（带 `FriendlyAppName` + 图标 + `SupportedTypes`），用来尽量让列表里多出一条显示正确的条目。若那条没出现，就用上面那条脚本宿主名。

> 根本解法是让命令里的 exe 变成真正的 `MDTiny.exe`（编译版启动器），这样名字和图标都能正常显示。当前用的是免编译的 wscript 方案，所以保留了这个瑕疵。

### 想手动指定（或系统里已手动选过 → `UserChoice` 优先级更高）

```
设置 → 应用 → 默认应用 → 按文件类型选择默认应用 → .md
   → 选「md-tiny」（找不到就选「Microsoft ® Windows Based Script Host」）
   → 设置默认值
```

Windows 不允许程序静默改 `UserChoice`（有哈希校验），所以只要你以前手动选过 `.md` 的默认程序，最后这一步就必须手工点一次；**没手动选过的话，安装脚本已经搞定，不用管这里**。

> 顺手一提：`reg add` 写 `REG_NONE` 时带 `/d ""` 会写成 2 字节，规范写法是 0 字节。脚本用「先 delete 再不带 `/d` 重建」来规避，不影响功能。

## 工作原理

```
双击 .md
   └─ 注册表 ShellExecute
        └─ wscript.exe //B open-md.vbs "<文件路径>"     ← 隐藏窗口，无黑框闪烁
             └─ node launcher.js "<文件路径>"
                  ├─ /api/ping 探活；没起就 detached 拉起 server.js
                  └─ 用默认浏览器打开
                       http://127.0.0.1:8765/?token=…&open=<绝对路径>&dir=<所在目录>
                            └─ server.js 读盘 → 页面渲染 → Ctrl+S → 原子写回原文件
```

### 唤起默认浏览器的方式

URL 带一次性 nonce → 打开 → 查 `access.log` 里有没有这个 nonce → 有就停手（**保证一次双击只开一个标签页**），没有才换下一种方式。三种方式在本机实测：

| 方式 | 结果 | 说明 |
| --- | --- | --- |
| `rundll32 url.dll,FileProtocolHandler <url>` | ✅ 250 ms / 1000 ms | 首选，无控制台窗口 |
| `cmd /c start "" "<url>"` | ✅ 250 ms | 次选；必须用 verbatim 命令行，否则 URL 里的 `&` 会把命令截断 |
| `explorer.exe <url>` | ❌ 未生效 | 仅作兜底 |

等待窗口给到 8 秒：**浏览器冷启动实测约 1.7 秒**，窗口太短会误判失败，然后兜底又开一个标签页。

手工验证链路（不写注册表）：

```
node launcher.js --no-open "C:\某目录\某文件.md"    # 只打印将要打开的 URL
```

## 打不开时的排查

按链路从前往后查。**每个环节都有日志，按顺序看，第一个没有新增行的文件就是断点**：

| 日志文件 | 有新行说明 | 没有新行说明 |
| --- | --- | --- |
| `vbs.log` | 文件关联确实调到了脚本宿主 | 关联没生效 / 安装目录被移动 / 脚本宿主被策略拦 |
| `launch.log` | node 起来了，能看到文件参数与 openUrl 用了哪种方式 | VBS 里 `sh.Run` 失败（同文件会写原因） |
| `access.log` | 服务端收到了请求：有 `GET /?token=…` = **浏览器真的把页面拉起来了** | 卡在「唤起默认浏览器」这一步 |
| `server-error.log` | 服务/接口报错（基本只在 500 时出现） | — |

常见现象：

| 现象 | 原因 / 处理 |
| --- | --- |
| 双击打开的还是别的程序 | `HKCU\...\FileExts\.md\UserChoice` 里是手动指定过的程序，优先级最高，需手工改 |
| 「打开方式」里看不到本应用 | `node install.js --dry-run` 看注册表是否写成功 |
| 关联突然失效 | 注册表记的是**绝对路径**，安装目录移动 / 改名了，重跑一次 `安装.cmd` |
| 改了关联但没生效 | 资源管理器有缓存，注销 / 重启一次即可；「设置」里的列表同理 |

> 日志都是纯文本，可以随时删，删了会自动重建。

## 为什么 Markdown 不能像 PDF 那样直接进浏览器？

思路是一样的，差别在**浏览器原生支持谁**：PDF 是浏览器内置的渲染能力，Markdown 不是。所以 `.md` 要进浏览器，中间必须有一个「牵线人」——把文件内容喂给页面，再把编辑结果写回磁盘。这就是本方案里那个几十 KB 的本地小程序。

| 做法 | 双击可用 | 能写回原文件 | 说明 |
| --- | --- | --- | --- |
| 浏览器扩展 | ❌ | — | `file_handlers` 只授权给 packaged app，扩展声明会被判安装警告，且在 Windows 上不注册关联（ChromeOS 独占） |
| 纯 PWA | ✅ | ✅ | 需要可访问的 https 源，首次双击要授权一次 |
| **本方案（本地服务 + 启动器）** | ✅ | ✅ | 100% 离线、无需公网、无需管理员、无需装扩展 |
| 重量级桌面应用 | ✅ | ✅ | 体验最好，但安装包普遍在数百 MB，与「轻」相悖 |

### 还能做成什么形态（难度对照）

| 形态 | 做法 | 难度 | 说明 |
| --- | --- | --- | --- |
| A. **当前形态（免编译）** | Node + wscript 启动器 | 已完成 | 不引入新二进制，规避智能应用控制 / 杀软；缺点是「打开方式」里名字显示为脚本宿主 |
| B. 原生启动器 exe | 用系统自带 `csc.exe` 编译 ~10 KB 的 C# 启动器，替换 wscript + vbs | **低** | 名字、图标都正常，不再依赖脚本宿主；注意：开启**智能应用控制**的机器可能拦未签名 exe |
| C. 安装包 | Inno Setup / NSIS 打成 `MDTiny-Setup.exe` | **低-中** | 需要先装打包工具；可做开始菜单、卸载项、自动写注册表 |
| D. 自带运行时的单文件 exe | Node SEA 把 node 运行时打进 exe | **中** | 用户机器上不用装 Node；体积 ~100 MB（node.exe 本身就 92 MB） |
| E. 自带运行时的单文件 exe | Node SEA / 打包运行时 | **高** | 用户机器上不用装 Node，但体积会到百 MB 量级，与「轻」的目标冲突 |

**编辑器本体（Markdown 解析、渲染、编辑、文件读写、安全桥接）占九成以上工作量且已全部完成；换成 exe 只是「外壳 / 分发」层面的事。**

> 安装目录建议别放在 `Downloads`（会被清理、会被误移）。注册表记的是绝对路径，一旦移动目录，关联就失效，需要重跑 `安装.cmd`。

## 卸载

```
node uninstall.js           # 只删注册表（保留代码）
node uninstall.js --purge   # 连 node-path.txt / config.json / 运行日志一起删
```

卸载只删除本程序自己的注册表项与值（`MDTiny.md`、`Applications\MDTiny.exe`、`Applications\MDTiny.md`），并从 `OpenWithProgids` 里摘掉自己那一个值，**不会**删除 `OpenWithProgids` 整个键（那会连带删掉其它程序的关联项）。扩展名的默认程序按 `assoc-backup.json` 还原。

## 自测（开发期）

自测脚本**不随本包分发**，只保留在源码仓库本地。发布前在源码树里跑过三层共 **109 项**断言：

- **接口与安全边界（29 项）** —— Token 鉴权、伪造 Host、路径穿越、原子写、mtime 冲突、BOM/CRLF 保留、目录列举，以及 `/api/ping` 的身份识别（`mine` / `root`）。
- **启动链路（23 项）** —— 服务按需拉起、复用已有服务、URL 参数、VBS 入口静态核对，以及端口被另一个副本占用时自动改用空闲端口（不复用别人的服务）。
- **端到端（57 项，需 Chrome）** —— 真实浏览器（CDP）跑「打开 → 渲染 → **富文本改写** → `Ctrl+S` → 磁盘内容核对」，逐字节核对 CRLF / BOM / 未改动块；再逐个验证 `.md` / `.markdown` / `.mdown` / `.txt` 都能写回原文件、**「打开」按钮选中的文件（只有句柄没有路径）也能保存**、保存失败必有提示，且无控制台异常。

编辑器内核的富文本层另有一套专项用例（35 项）：同一套断言对扩展页面与本包页面各跑一遍 —— 这是「双端行为一致」最直接的验证方式。

> 这些脚本运行时会先探测端口：若 `config.json` 里的端口已被占用（例如本机另装了一份正在运行的实例），
> 自动换一个空闲端口再跑，收尾也只结束自己拉起的那个进程 —— 不会连到、更不会影响你正在用的实例。

## 已知限制

- 「打开方式」列表里本程序显示为 **「Microsoft ® Windows Based Script Host」** —— 因为命令用的是 `wscript.exe`，Windows 按 exe 取名。想显示成「md-tiny」，需要换成编译版的 `MDTiny.exe` 启动器（本项目为免编译依赖，暂未采用）
- 若系统里 `.md` 已被**手动指定**过默认程序（`UserChoice`，有哈希保护），脚本改不动，必须在「设置 → 默认应用」里手工点一次
- 需要本机有 Node.js（只用它来跑服务，不装任何 npm 依赖）
- 文件名含 `%` 等特殊字符时由 `encodeURIComponent` 处理；极端文件名建议先改名
- 目前只读 UTF-8 编码的 Markdown；GBK 文件会显示为乱码
- 侧栏文件树与文件关联只覆盖 **`.md` / `.markdown` / `.mdown` / `.txt`**（服务端按这份白名单过滤）。
  `.txt` 的系统关联需要在安装时加 `--with-txt`（默认只注册前三种）；再往外的扩展名（`.log` / `.json` …）
  既不会出现在侧栏、双击也不关联，属于既定范围而非缺陷
- 用「打开」按钮选中的文件（而不是双击关联或侧栏点开的），在本地服务模式下由浏览器文件句柄直接写回，
  **不经过服务端的原子写与 mtime 冲突检测** —— 这是浏览器能拿到文件的唯一途径（网页拿不到本地绝对路径）
- 富文本层只覆盖 marked 会产出的那套标签，文档里**手写的原始 HTML 段与链接定义不参与编辑**（整块原样带走，界面中标灰）
- **混合行尾**（同一份文档 CRLF 与 LF 混杂）在编辑保存后按**多数派统一**；只有「一个字符都没改」时才逐字节回放
- 编辑态里输入 `2 * 3 * 4` 这类**成对符号**，保存后会被 Markdown 当成斜体语法 —— 行内语法靠 DOM 结构表达，是该实现方式的固有代价
